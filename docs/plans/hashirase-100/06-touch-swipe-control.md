# 06 タップ位置を起点にしたスワイプ運転（スマホ標準操作）

作成日：2026-10-22／対象：`chameleonjp-lab/hashirase`

この文書はユーザーが希望した**スマホでの主操作を、固定のアクセル・ブレーキ・左右ボタンから「タップした場所を起点に指を動かす方式」へ変更する**ための詳細仕様です。前提となる２モード、端末別設定、右側通行、追跡5台、100点評価は変えません。

## 1. ユーザー決定と今回の設計案

**ユーザー決定:** スマートフォンではペダル式ボタンを主操作にせず、タップ位置を起点にスワイプで運転する。ゲームと現実寄りのシミュレーターに対応する。

**設計案（レビュー時に調整可能）:** どの方向にも動かせる画面内の操作可能領域を使用する。操作量の調整範囲は感度で調整できる。下方向での後退切替は安全のため停止を条件とする。初期数値・後退への遷移条件は実機検査で調整できるが、テストと文書を同時に更新する。

| ジェスチャー | 操作 |
|---|---|
| ゲーム領域をタップ、移動なし | その位置を中心として記録。加速・ブレーキ・操舵は0 |
| 起点から上へ移動 | 指の移動量に応じて前進加速 |
| 起点から下へ移動 | 前進中は減速・制動、停止を確認した後に後退へ移行 |
| 起点から左右へ移動 | 移動方向と距離に応じて左右に操舵 |
| 斜め移動 | 縦の加減速と横の操舵を同時入力 |
| 起点に戻す | 加速・ブレーキ・操舵を0 |
| 指を離す／キャンセル | 全スワイプ入力を0。制動入力を持続させず惰性走行（物理による減速は残る） |

ゲーム中にタップした位置を固定の起点として保持し、指の移動で起点自体は移動しない。起点には透明な円と入力位置を表示できる。表示を切っても操作は可能とする。指の位置に依存して主要ペダルや左右ボタンを固定表示しない。

## 2. 入力の数学的な約束

入力取得は`src/platform/swipe-control.js`の`createSwipeController(settings)`で行い、`pointerdown`時の`pointerId`と`clientX/clientY`を記録し、`pointermove`で差分を計算する。`SwipeFrame`は`{horizontal, vertical, active, pointerId}`で、`horizontal`は右を正、`vertical`は上を正、各`[-1,1]`。画面座標系の下方向への増加に注意する。

初期提案値：**無反応範囲10 CSSピクセル、最大入力までの基準距離88 CSSピクセル**。デッドゾーンを超えた距離を0〜1へ線形換算し、両軸を別々に制限する。斜め入力でも片軸だけが消えない。ドラッグ中の感度変更・端末回転は入力を一度解放し、起点を再取得する。

起点付近と画面端では不自然な急加速・急操舵を起こさない。画面端からの開始について操作可能距離を検査し、必要なら有効半径を安全に調整する。数値は初期案であり実測済みではない。

`SwipeFrame`は共通の`InputFrame`へ変換する。前進は`throttle`、減速は`brake`、後退駆動は`reverseThrottle`（新しい任意フィールド、0..1）で渡し、`steer`は左右の値を渡す。**前進中に下へ滑らせた瞬間、逆方向への駆動力を掛けない。** 停止の閾値（初期案0.15m/s以下）と後退への切替猶予（初期案300ms）を満たしてから`reverseThrottle`へ移る。前進・後退・制動を同時に最大入力にしない。ゲームとシミュレーターは同じ入力形式を受け取り、車の実際の運動は各モードの独立した物理が決定する。

## 3. 操作領域と指の所有権

- `index.html`のゲーム表示領域に、操作受付レイヤーを設ける。**画面内の操作可能な余白**ならタップ位置がどこでも起点になる。ただしホーム・設定・説明・結果・画面上のボタン・リンク・モーダルは除外する。画面全体へ`touch-action:none`を設定してブラウザの通常操作を壊さない。
- 最初に受付した1本を運転用の`pointerId`として固定する。2本目の指は運転スワイプを奪わず、別に存在するロケット・ジャンプ・カメラ等の操作ボタンを押せる。1本目を離した後に2本目を自動昇格させて意図せず加速しない。
- 運転操作領域だけ必要に応じて`touch-action:none`と`setPointerCapture`を使用し、画面外への移動と`lostpointercapture`を扱う。`pointercancel`・`pointerup`・`blur`・`visibilitychange`・端末回転・モード離脱・エラーで全運転入力を解除する。
- カメラ切替は明示した別操作にする。運転のための横スワイプをカメラ回転として扱わない。ホームや設定のスクロール・タップ・文字拡大を妨げない。
- 自動アクセルと従来のペダルボタンは**初期表示OFF**。必要な代替操作がある場合はアクセシビリティ用の任意設定に限定し、主操作のスワイプと競合させない。ゲームのロケットやスタント用の明示ボタンは残してよい。シミュレーターで使用しない特殊ボタンは表示しない。

## 4. 設定・表示・アクセシビリティ

`touch/desktop/hybrid × driving/simulation`の既存保存区分を維持する。スマホの基本設定には「スワイプ感度（左右／前後）」「無反応範囲」「最大入力までの移動距離」「操作位置ガイド表示」を置く。範囲は不正値に対して検証する。PC標準はキーボード・マウス、タッチPCは入力源を判別し両方式を利用できる。操作領域の案内と切替方法をホームの説明・ゲーム内ヘルプへ追加する。

音声読み上げとキーボード操作を必要とする利用者へは、設定から代替の明示的操作を選べるようにする（標準画面でペダルを常時表示しない）。ゲーム内の特殊ボタンと設定の操作対象は44×44 CSSピクセル以上を維持する。カーソルやガイドは速度・HP・方向案内を隠さず、縦横・Safariのバー表示変化・安全領域に対応する。

## 5. 実装・検査との対応

| 変更先 | 必須内容 |
|---|---|
| **T02** | `SwipeFrame`と`InputFrame.reverseThrottle`を契約に追加。数値範囲と競合解消を単体検査 |
| **T05** | ホーム・モーダル・設定ではスワイプ運転を開始させない。モード切替時に指の状態を解放 |
| **T06** | 動く起点・2軸同時入力・上下制動/後退・複数指管理・保存・PC併用を実装 |
| **T08/T10** | `InputFrame`を各モードの独立した車両挙動へつなぐ。ゲーム操作補助と現実寄りの計算を混同しない |
| **T13** | 起点表示・初回案内・アクセシビリティの代替操作を仕上げる |
| **T14** | 中断・復帰・読み込み失敗・モード離脱時の入力の完全解除 |

受入検査は既存の**A01〜A60の60件を維持**し、A31〜A40の条件を更新する。基本入力確認はA06、入力反映遅延はA46にも含める。実機未測定をPASSにせず、6評価軸の配点（5要求×20点）も変更しない。
