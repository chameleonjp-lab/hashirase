# 02 完成仕様と設計

## 1. 2モードの違い

ここで示す細かな方式・数値は計画提案です。ユーザーの確定要件を変えるものではありません。

| 項目 | ドライビングゲーム | 現実の物理に近い車両シミュレーター |
|---|---|---|
| 主な目的 | 市街地走行、タイムアタック、追跡、スタントを楽しむ | 条件を変えて加減速・旋回・接地の変化を測る |
| 走行場所 | 試験場／NY風市街地 | 車両試験場／交通ありの自由走行 |
| 物理 | 操作しやすい補助付き。ロケット・吸着・自動姿勢補正を明示 | 質量・力・四輪の接地・摩擦・車体運動を計算。補助のON/OFFを記録 |
| 衝突・損傷 | HPと部位損傷。警察ダメージ倍率などはゲームルール | 接触速度・力積と部位機能の近似。HP倍率・自動復活は持ち込まない |
| 記録 | ルール条件別のタイム・得点・失敗理由 | 加速時間、制動距離、横加速度、入力と姿勢の時系列 |
| 警察 | 追跡最大5台、検問、ヘリ | 標準では出動しない。交通を観察できる |
| 実車との関係 | 非公式・架空の設定と表示 | 説明用の近似モデル。実車未検証値は「推定」と表示 |

ゲームの4つの遊び（試験場、自由走行、タイムアタック、追跡）は入口・説明・終了・再挑戦を持ちます。新しい大規模ゲームモードは増やしません。シミュレーターは直線加速、定速からの制動、定常円旋回、左右で摩擦が異なる制動、スラロームを用意します。

## 2. 方式の比較と採用案

| 方式 | 利点 | 問題 | 判断 |
|---|---|---|---|
| 今の結合ファイルにモード条件を増やす | 変更箇所が少ない | 未選択側まで読み込み、共有状態と修正競合が残る | 不採用 |
| 全面書き直し・別アプリを2つ作る | 分離が明確 | 既存演出の欠落と重複保守が起きやすい | 不採用 |
| 共通の描画・操作を残し、ルール・物理・状態を段階的に分ける | 既存資産を検査しながら移せる | 途中期間の旧処理との境界管理が必要 | 採用 |

必要になった時点で処理を取得する仕組みを使います。これを動的読み込み（dynamic import）と呼びます。ホームから静的にゲームや3Dエンジンをimportしません。ビルドはJavaScript標準モジュールとesbuildの分割出力を案とし、開発時だけビルドツールを使います。実行時フレームワークは新設しません。

Node.jsは既存の22系列を出発点にし、導入時にサポート状況・既知問題を確認します。Three.jsの更新は部品分離と同じPRで行いません。まず現行r128の扱いを固定し、更新が必要なら互換試験付きの独立作業にします。開発依存の具体的な版はT02で調査してlockfileに固定し、実行時の`latest`参照は禁止します。

## 3. 目標フォルダ

```text
index.html                     # ホームの入口。巨大なゲームHTMLを置かない
src/
  app/                         # 起動、ホーム、モード選択、状態遷移
  contracts/                   # 入出力の型・検証・イベント定義
  platform/                    # 端末判定、入力、設定、保存、時計、音
  rendering/                   # Three.js描画、カメラ、資源管理、画質
  world/                       # 道路・信号・交通・周辺読み込み・世界状態
  physics/shared/              # 数学、衝突形状、共通の計算補助
  modes/driving/               # ゲーム専用の状態、ルール、物理、得点、追跡
  modes/simulation/            # 車両モデル、試験手順、計測、比較
  assets/                      # 車体・都市・音・素材定義。権利情報も管理
  ui/                          # ホーム・設定・結果の共通部品
  legacy/                      # 移行中のみ。最終的に公開経路から外す
styles/                        # 共通／ホーム／ゲーム／シミュレーター別
public/                        # 固定素材・ライセンス表示
scripts/                       # build、依存境界検査、測定、公開検証
tests/                        # unit、integration、e2e、physics、performance
docs/                         # 仕様、計画、証拠への索引
dist/                         # 生成物。手編集禁止、配備元
```

`src/runtime/*.part.js` と巨大な `assets/js/simulator.js` は移行期間だけ残します。最終候補では公開側から参照しません。旧コードへの戻しは旧コミットへのロールバックで行い、両実装を常時読み込む方式にはしません。

ファイルを機械的に等分するのではなく、状態を持つ単位に `create...()` を置きます。1ファイル400行を見直し目安とし、越える場合は責務と検査の分け方をPRで説明します。行数を満たすためだけの分割はしません。

## 4. 部品間の約束

次の表はT02でJavaScriptの型注釈と検査として固定する契約です。名前を後続担当が独自に変更しません。

| 部品 | 公開する入口 | 所有するもの／禁止する依存 |
|---|---|---|
| モード | `createMode(context, options): Promise<ModeSession>` | モード固有の状態。相手モードのimportは禁止 |
| 実行中モード | `start()` / `pause(reason)` / `resume()` / `step(dt,input)` / `snapshot()` / `dispose()` | 終了は何度呼んでも安全。独自の無限描画ループは禁止 |
| 物理 | `createVehicleModel(config)` → `reset(initial)` / `step(dt,input,environment)` / `snapshot()` | 数値だけを保持。DOM・Three.js・音・保存へ依存しない |
| 世界 | `createWorld(seed, config)` → `step(dt)` / `query(bounds)` / `reset(seed)` / `dispose()` | 道路・接触対象・信号の正本。カメラ距離で物理状態を消さない |
| 描画 | `createRendererHost(container, quality)` → `render(snapshot, alpha)` / `resize(size)` / `dispose()` | 3Dオブジェクト・描画資源。得点や車の速度を変更しない |
| 入力 | `createInputService(profile)` → `sample()` / `clear()` / `dispose()` | 指・キー・マウスを個別追跡し、共通の入力へ変換 |
| 設定 | `createSettingsStore(storage)` → `read(profile,mode)` / `write(profile,mode,value)` | 検証済み値のみ返す。保存不能時はメモリに切り替える |
| 追跡 | `createPursuitManager(config)` → `step(dt,world,player)` / `snapshot()` / `reset()` | 追跡車ID・順序・台数・増援時計。描画の所有者ではない |

`InputFrame` は `throttle/brake: 0..1`、`steer: -1..1`、`boost/hover/kickflip: boolean`。キー割当・タッチ配置は別データです。シミュレーターでは非対応のスタント入力を無視し、設定にも出しません。

`VehicleSnapshot` は `position: {x,y,z}`、`rotation: quaternion`、`velocity`、`angularVelocity`、`wheels[4]`、`damage`、`telemetry` を持ちます。値はメートル・秒・キログラム・ラジアンで統一し、画面でだけkm/hやmphへ変換します。

`context` は `clock/input/settings/world/renderer/audio/events/abortSignal/sessionId` を名前付きで受け取ります。巨大な可変オブジェクトを何でも入れられる共有置場にしません。世界や描画がまだ不要な段階はfactoryを渡して後から生成します。

イベントは `eventId/sessionId/type/simTime/payload` を持ち、得点の加算は同じeventIdにつき一回です。相手の内部変数を直接書き換えません。描画・UIには読み取り専用の結果を渡します。

依存方向は「app→mode→contracts/platform/world/physics」「rendering→contracts/assets」です。`physics`から`rendering`、共通領域から`modes`、`driving`と`simulation`の相互参照を禁止します。テストでimport関係を検査します。

## 5. 読み込み・終了・失敗

ホームは文字・CSS・静的なサムネイルと設定だけです。ホームに動く3D背景を置かず、事前取得やService Workerの先読みで未選択モードを読み込むことも禁止します。

選択時は対応表で許可した `driving` / `simulation` だけを取得します。URL文字列をそのままimport先に使いません。選択直後に連打されても最新の選択だけを起動します。import自体をキャンセルできると仮定せず、世代番号と終了フラグで古い完了結果を破棄し、後から生成された資源も解放します。

状態は `HOME → LOADING → READY → RUNNING ↔ PAUSED → RESULT → DISPOSING → HOME`。ロード失敗は `ERROR` へ進み、「再試行」「ホームへ」を出します。画面を隠しただけで計算を続ける方式は禁止です。再試行は重複ループ・音・イベントを作りません。

戻る／モード変更では入力、描画ループ、タイマー、イベント、音声接続、3D部品、画像テクスチャ、ワーカーを所有者ごとに終了します。共有資源は参照数を管理します。ブラウザのモジュールキャッシュが残ることと、使っていない場面が動き続けることを区別します。メモリ解放のためにURLへ毎回時刻を付けてimportし直す方法は使いません。

画面非表示・フォーカス喪失では入力を全解放して中断し、復帰時は再開操作を要求します。WebGLが使えない場合は、壊れた簡易描画で「成功」に見せず、診断と再試行・ホームを表示します。完全な2D代替ゲームは今回の完成条件に含めません。

## 6. スマホ・PC・設定

幅だけで端末を決めず、`pointer/hover`、タッチ能力、現在の入力を使います。タッチPCは両入力を使える状態にし、入力が変わっただけで設定値を勝手に消しません。判定を手動で切り替える項目も置きます。

| 共通設定 | スマホで出す項目 | PCで出す項目 |
|---|---|---|
| 画質、30/60fps、音量、視点、揺れ軽減、速度単位、表示サイズ | ボタンサイズ・位置、左右配置、ステア感度、タッチカメラ、自動アクセル | キー割当、マウス感度、ドラッグ視点、キー同時押しの説明 |

保存キーは `hashirase:settings:v1:{profile}:{mode}`。profileは `touch/desktop/hybrid`、modeは `driving/simulation`。シミュレーターの物理条件とゲームの難易度は分けます。設定初期化は対象範囲を明示し、記録を巻き込んで消しません。

タッチ領域は44×44 CSSピクセル以上、主要ペダルは標準56以上を目標にします。両親指で操舵＋加速ができ、追加操作を無理な指の交差なしで使える配置にします。速度・HP・目的地を常時、細かな計器は折りたたみます。設定は走行を中断して開きます。

ゲーム領域だけブラウザ操作との競合を抑え、ホーム・設定・説明では文字拡大を妨げません。200%表示、縦横切替、Safariのバー表示変化、安全領域を検査します。読み上げ対応はホーム・設定・結果・重要通知を対象とし、音声だけで3D走行を完全に遊べるとまでは主張しません。

## 7. 右側通行と信号

座標は+xが東、+zが南、+yが上です。北向き（-z）は道路中心より+x、南向き（+z）は-x、東向き（+x）は+z、西向き（-x）は-zの車線を使います。

レーンに `laneId/direction/centerline/intersectionId` を持たせます。生成、走行、再配置、車線変更、右左折、信号表示、停止線を同じ道路データから決めます。配列indexを座標の等間隔式で推定しません。交通量の種別と方向を別の乱数系列で選び、車両IDの偶奇で全方向が消える作りをやめます。

右左折を含む全方向のテストを用意します。これは架空都市内で定義した交通ルールであり、現実のニューヨークの一方通行や全交通法規を再現すると説明しません。一般車は原則右側を守り、プレイヤーの逆走は操作を禁止せずゲーム内で扱います。警察の緊急走行は別ルールとして表示し、通常交通の逆走バグと混同しません。

## 8. 追跡5台と最後尾入替

増援間隔は既存の30秒を維持する案です。一般車接触3回で追跡開始、開始時1台。以降、追跡が動いている時間で30秒ごとに1台追加し、5台になるまでは消しません。停止・結果表示・ホームでは時計を進めません。

5台いるときの「最後尾」は、プレイヤーの実際の水平進行方向に沿った前後位置で決めます。速度1m/s未満は直前の有効な進行方向、それもなければ車首方向を使います。後退中は後退する方向を基準にします。

`f = normalize(playerVelocityXZ)`、`p = dot(unitPositionXZ - playerPositionXZ, f)` として、pが最小の車を退場させます。同点は距離が大きい車、その次は生成IDが小さい車にします。全車前方にいる場合もp最小を使い、決定が揺れないようにします。

新しい車の安全な位置を先に確保し、その後に1台退場→1台生成を1回の更新で行います。フレーム途中も有効台数6台を作りません。壁の内部、他車との重なり、プレイヤーとの予測衝突まで2秒未満の位置は候補から除きます。安全な位置がなければ旧車を残して1秒後に再試行し、予約台数を積み上げません。

追跡開始0秒で1台、30/60/90/120秒で2/3/4/5台、150秒以降は5台のまま入替です。遠方車の再配置も同じ管理を通し、定時増援と二重生成しません。車IDは単調増加し、配列位置をIDとして再利用しません。

「最大5台」は動的に追う車両を指す提案です。既存の固定検問車2台とヘリは別枠で画面にも区別します。検問車を動的追跡へ加える拡張では5台枠に算入します。全警察車を合計5台にしたい場合は、この定義と検査を変更してから実装します。

## 9. ゲームルール・得点・記録

競争用のコースはシード、目的地、道路距離、車種、天候、難易度、補助、物理バージョンを固定します。「約3.8km」は直線距離であり、同じ長さの道順とは限らないため、条件が違うコースの最速記録を混ぜません。

得点案は、未通過の進行区間による上限付き加点＋ゴール固定点＋時間点＋残HP点＋重複しないスタント点−違反減点です。進行の加点は区間IDにつき1回とし、往復や周回で稼げません。ゴール固定15,000、時間点 `max(0, round((150-activeSeconds)*100))`、残HP点 `round(hp*8)`、物損150・一般車350・警察700の減点を出発点にし、バランス調整は定数ファイルとルール版を同時更新します。検問突破500点は独立したイベントとして保存し、ゴール時に上書きしません。

地上の円だけでなく、高さを含む可視ゴール領域（初期案：半径24m・高さ16m）と移動経路の交差で到達判定します。高速で通り過ぎても検出します。HP0とゴールが同一更新で起きる場合は、接触・損傷を解決して生存していることを優先条件にします。

結果を確定した後は得点・HP・追跡・タイマーを凍結します。結果には各点の内訳、失敗理由、再挑戦・ホームを出します。自由走行は練習記録として分けます。途中で車・物理・天候・補助・目的地を変えた走行は条件別の練習記録にし、競争用ベストを更新しません。

## 10. 物理と時間

描画とは別に一定間隔で運動を計算します。固定時間刻み（fixed timestep）の初期案は両モード1/120秒、1描画につき最大8回です。描画は30/60fpsから選び、120Hzの物理が端末で維持できるかT12/T17で測ります。計測前に「iPhoneで問題ない」と断定しません。

処理落ちで未処理時間を黙って捨てたり、画面復帰後の時間を一気に追いつかせたりしません。追いつけない場合は中断して通知し、その競争記録を無効にします。競争時間は一時停止を除く単調時計で計り、シミュレーション時間との差が100msを超えて滞留したら無効とします。低性能端末の遅い計算を速いタイムとして記録しません。

ゲーム側は地上・壁面・空中の遷移条件と補助を明示し、燃料ゼロ、低速、逆走、着地、転倒での例外を検査します。無燃料のジャンプや空中での無制限回復を認める場合は、遊びの仕様として明示します。初期案では回復は地上かつ非噴射時に限ります。

現実寄り側は重力9.80665m/s²、車体の質量・慣性、重心、軸距・輪距、四輪の接地点、ばねと減衰、タイヤの縦横滑り、前後左右の荷重移動、駆動トルク、ブレーキ、空気抵抗、転がり抵抗から計算します。旋回速度を直接書き換えたり、損傷で質量を無視した定数加速を与えたりしません。回転剛体と四輪接地のモデルを採用し、タイヤの力を合成して摩擦限界を超えないようにします。

最初のT04では直線の力と速度を計算する最小モデルを作り、T10で四輪・旋回・上下運動へ拡張します。最小モデルを最終シミュレーターと表示しません。Teslaの未確認の重量・推力・公式年式を確定値として流用せず、推定のデモ車パラメータには出典区分・単位・上下限・版を持たせます。

高速衝突では移動前後の軌跡を調べる連続衝突判定（CCD）を使います。車体の回転を反映した接触形状と、接触点の力積から並進・回転へ反映します。外板の見た目の変形は物理から得る接触情報に対応させますが、金属破壊や人体安全を精密計算するモデルとは表示しません。

## 11. 都市・描画・資源

道路と建物の軽い定義データと、3Dオブジェクト生成を分けます。都市は200m四方の区画を初期案とし、周辺だけを生成します。描画半径は画質別300/500/700mを出発点にします。衝突対象は現在位置だけでなく、最高速度で3秒先に到達する範囲まで準備し、非表示だから衝突しない状態を作りません。

電柱・建物・道路・小物は共通形状と材質を使ってまとめて描きます。壊れた物だけ個別表示へ移し、元に戻す／再訪する条件を世界状態に保存します。非表示化と破棄を区別し、未使用キャッシュにはサイズ上限と使用順の退避を設けます。定期的に全キャッシュを消す方式は禁止です。

煙・破片・雨・スキッドマークは上限付きの再利用プールを使います。物理更新・交通判断・画面テキスト更新・描画の頻度を分け、UI更新は原則10Hz、重要イベントは即時反映します。性能の詳細な合格値は04にまとめます。

## 12. 外部資料から採用した技術上の注意

以下は実装方針の根拠であり、当ゲームの動作確認ではありません（参照日2026-10-22）。

- [MDN import()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import)：必要時の取得とモジュールキャッシュを考慮する。キャッシュの完全消去を保証しない。
- [Three.js Cleanup](https://threejs.org/manual/pages/cleanup.html)：画面から外すだけでなく、所有するgeometry/material/texture等の明示解放を設計する。
- [MDN Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)：非表示の検出を中断・資源停止に使う。
- [MDN Pointer events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)：指ID、キャンセル、取得解除を入力状態の解放へ結び付ける。
- [Playwright Emulation](https://playwright.dev/docs/emulation)：画面サイズ・タッチなどの模擬試験を使う。模擬試験をiPhone実機試験と呼ばない。
- [esbuild Splitting](https://esbuild.github.io/api/#splitting)：分割出力とimport関係の記録を読み込み境界の検査に使う。
