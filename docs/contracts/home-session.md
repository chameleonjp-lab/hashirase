# ホームとモードの所有（T05）

`index.html` は `dist/app/main.js` と共通UIだけを読む。`loadMode` の許可値は driving / simulation の2つで、import先はすべてリテラル。選択した実行系・画面・CSSだけを遅延取得する。ゲーム用Three.js・音声コードはシミュレーターにもホームにも含めない。

アプリのhostだけがRAFと固定時計を所有する。HOME → LOADING → READY → RUNNING ↔ PAUSED → RESULT → DISPOSING → HOME。終了したゲームのルールを見てRESULTへ移り、入力・時計・音を停止する。RESULTからリセットして再開できる。最小シミュレーターの試験結果UIはT11で追加する。

選択ごとに世代番号、AbortController、ResourceScopeを発行する。選択変更では旧世代を同期的に無効化し、所有資源の解放後に新しい画面を用意する。取消不能のimportは待たずにHOMEへ戻るが、古い結果ではfactoryを呼ばない。遅れて戻ったcontext/sessionのdisposeも資源一覧へ登録する。ScopeはLIFO、重複登録を除外、途中のdispose例外でも残りを解放する。

取得・初期化・フレーム処理の失敗はERRORへ進み、部分的な画面も廃棄する。15秒の読み込み上限を設ける。再試行は許可済みmodeのURLを再読込する（ブラウザが失敗したES module importを記憶するため）。ERRORの生の技術情報は診断値へ残し、利用者には日本語で案内する。WebGL消失でも先に旧セッションを解放する。BFCacheからの復帰は再読込する。

非表示・blur・画面回転・設定・操作説明で中断し、自動再開しない。読み込み中の中断要求も次の起動まで保持する。固定時計が100ms超の遅延を検出した場合は過負荷として中断し、リセットを案内する。時間の上限を緩めない。

T06のInputServiceを固定tickごとに1回だけsampleする。速度とdtを渡して後退猶予を管理する。手動の端末変更時は同じModeContextの入力portの内側で旧binderを破棄して作り直す。設定・home・modalは運転面の外に置く。旧キー/ペダル入力は無効化し、専用RCSはゲームの名前付きactionへ渡す。

画質・描画頻度・音量・速度単位・カメラ・揺れ軽減・表示サイズを接続する。シミュレーターの無音・直線モデルに不要な音量/運転席/揺れ設定とゲーム特殊操作は表示しない。シミュレーターの表示操作は拡大・縮小とパンで、旋回する車両計算を装わない。端末/モードごとの6レコードだけを検証して保存し、保存不能時はT06の警告とメモリ保持を使う。

ゲーム画面はローカル生成したCSSをモードrootへ限定して適用する。終了時にlinkとDOMを解放する。ゲームのミニマップは小さな私有bitmapからimgへ転写し、既存の地図を保ちながらDOM上のcanvasを1つにする。このbitmapと旧来のテクスチャ生成用canvasは画面の描画ループやGPU contextを持たず、所有者が破棄する。旧入口 `legacy.html` は原本保護/回帰検査に残す。

`appDiagnostics()` はセッション/RAF/初期化/DOM canvas/入力/描画/音の診断を返す。製品画面には内部契約名や試験用操作を表示しない。ブラウザ自動検査のRAFは手動で進めるため、実機fps、入力遅延、長時間メモリ収束の証明には使わない。
